# ejabberd_ynh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A catalog-submittable YunoHost app that installs ejabberd as an XMPP server integrated with YunoHost (LDAP/SSO, certs, DNS, permissions), passing the XMPP Compliance Suite.

**Architecture:** ejabberd (Debian package) as a YunoHost packaging-v2 app. One vhost = the YunoHost domain with `conference./pubsub./upload./proxy.` subdomains. LDAP auth against YunoHost's directory (permission-gated), mnesia storage, YunoHost-managed certs, coturn (auto-installed) for A/V advertised via `mod_stun_disco`. nginx serves `.well-known/host-meta` and proxies BOSH/WebSocket. Hybrid build: `example_ynh` skeleton + XMPP integration lifted from `prosody_ynh` + fresh ejabberd config.

**Tech Stack:** YunoHost packaging v2 (`manifest.toml`, `ynh_*` helpers), bash install scripts, ejabberd YAML config, nginx, mnesia.

**Reference sources (read these for exact helper signatures & patterns):**
- `~/repos/project-chat/prosody_ynh/` — the canonical XMPP↔YunoHost app to mirror (scripts, manifest resources, nginx, DNS hook, config panel, backup/restore).
- `github.com/YunoHost/example_ynh` — current packaging-v2 conventions.
- `docs/superpowers/specs/2026-08-04-ejabberd-ynh-design.md` — the approved design (source of truth for decisions).
- The tested ejabberd config lives on `ejabberdtest.mayer.rocks:/etc/ejabberd/ejabberd.yml` (adapt it: swap ACME→YunoHost certs, internal-auth→LDAP, add coturn).

## Global Constraints

- `packaging_format = 2`; app `id = "ejabberd"`; `multi_instance = false`.
- Target **YunoHost 13 / Debian Trixie**; ejabberd from the **Debian `ejabberd` package** (no third-party build).
- Auth = **LDAP** against `ou=users,dc=yunohost,dc=org`, permission-gated (`permission=cn=ejabberd.main,...`). Accept PLAIN-over-TLS (no SCRAM — YunoHost/issues#2829).
- Storage = **mnesia** (no SQL dependency).
- TLS = **YunoHost certs** at `/etc/yunohost/certs/__DOMAIN__/{crt,key}.pem`; reload ejabberd on renewal.
- **coturn** is a soft dependency: auto-install if absent, advertise via `mod_stun_disco`. Never run ejabberd's built-in `ejabberd_stun`.
- License **AGPL-3.0** (matches ejabberd).
- **Cannot** co-install with prosody_ynh/metronome_ynh (5222/5269 clash) — state in PRE_INSTALL/DESCRIPTION.
- Out of scope: Matrix gateway, SQL, SCRAM, clustering.
- Every script is idempotent and passes `shellcheck`; `ejabberd.yml` renders to valid YAML that `ejabberdctl` accepts.

## File Structure

```
manifest.toml               app metadata, install arg (domain), resources (apt/ports/permissions/system_user/data_dir/install_dir)
scripts/_common.sh          _ejabberd_configure(): read coturn settings, render ejabberd.yml + nginx, cert wiring; shared vars
scripts/install             provision, apt ejabberd, auto-install coturn, configure, permissions, dns hook, start, checks
scripts/remove              stop, apt remove/purge, drop nginx + dns hook
scripts/upgrade             re-run configure idempotently; preserve mnesia
scripts/backup              mnesia spool + /etc/ejabberd + settings
scripts/restore             restore spool + config + perms + nginx + dns hook
conf/ejabberd.yml           the ejabberd config template (heart of the app)
conf/nginx.conf             .well-known/host-meta + /http-bind (BOSH) + /ws proxy to ejabberd :5443
conf/well-known_host-meta.xml  XEP-0156 connection methods
hooks/custom_dns_rules      SRV (relative names) + CNAME subdomains
config_panel.toml           registration toggle, http_upload size/quota/expiry
tests.toml                  package_check test matrix

LICENSE (AGPL-3.0)  README.md (generated by YunoHost bot; stub for now)
```

location = /.well-known/host-meta {
    alias /var/www/.well-known/__DOMAIN__/host-meta;
    default_type 'application/xrd+xml';
    add_header Access-Control-Allow-Origin '*';
}
location /http-bind {
    proxy_pass https://127.0.0.1:__PORT_HTTP__/bosh;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

### Task 5: `scripts/_common.sh`

**Files:** Create `scripts/_common.sh`.

**Interfaces:**
- Produces: `_ejabberd_configure()` used by install/upgrade/restore. Reads coturn settings; exports `turn_host`, `turn_port`, `turn_secret`, `http_upload_size`; renders `conf/ejabberd.yml`→`/etc/ejabberd/ejabberd.yml`, nginx, host-meta; wires cert reload.

- [ ] **Step 1: Write `_common.sh`** (mirror `prosody_ynh/scripts/_common.sh` structure)

```bash
#!/bin/bash

app=ejabberd

_ejabberd_configure() {
    # coturn (auto-installed by scripts/install if absent)
    turn_secret=$(ynh_app_setting_get --app="coturn" --key=turnserver_pwd)
    turn_port=$(ynh_app_setting_get --app="coturn" --key=port_turnserver_tls)
    turn_host="$domain"

    ynh_app_setting_set_default --key=http_upload_size --value="104857600"
    http_upload_size=$(ynh_app_setting_get --key=http_upload_size)

    # Render ejabberd config (ynh_config_add substitutes __PORT_CLIENT__ <- $port_client, etc.)
    mkdir -p "$data_dir/upload"
    chown -R ejabberd:ejabberd "$data_dir"
    ynh_config_add --template="ejabberd.yml" --destination="/etc/ejabberd/ejabberd.yml"

    # nginx + well-known
    ynh_config_add --template="nginx.conf" --destination="/etc/nginx/conf.d/${domain}.d/ejabberd.conf"
    mkdir -p "/var/www/.well-known/${domain}"
    ynh_config_add --template="well-known_host-meta.xml" --destination="/var/www/.well-known/${domain}/host-meta"
    chmod 644 "/var/www/.well-known/${domain}/host-meta"

    # ejabberd must read YunoHost certs (group perms) + reload on renew
    usermod -aG ssl-cert ejabberd || true
}
```
